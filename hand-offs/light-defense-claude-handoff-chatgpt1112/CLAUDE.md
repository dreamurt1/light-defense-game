# Claude Code Project Instructions — LIGHT DEFENSE

## 1. 작업 전 필수 절차
- 작업 시작 시 현재 저장소의 디렉터리 구조, package scripts, 프레임워크, 렌더링 방식, 입력 처리, 게임 루프, 저장 방식, Firebase 설정을 먼저 조사한다.
- 현재 코드가 구버전 기획을 구현하고 있다면, 먼저 `docs/GAME_DESIGN.md`와 비교한 차이 목록을 작성한다.
- 기존 에셋과 동작 중인 기능을 임의로 삭제하거나 전면 재작성하지 않는다.
- 변경 전 영향을 받는 파일과 마이그레이션 계획을 짧게 제시한다.
- 한 번에 큰 기능을 여러 개 구현하지 말고 `docs/IMPLEMENTATION_PLAN.md` 순서대로 작은 단위로 진행한다.
- 각 단계 후 빌드·타입 검사·테스트를 실행하고 결과를 보고한다.

## 2. 문서 우선순위
1. `docs/GAME_DESIGN.md` — 게임 규칙과 콘텐츠의 기준
2. `docs/OPEN_QUESTIONS.md` — 미확정 사항. 임의로 확정하지 말 것
3. `config/game-balance.json` — 조정 가능한 초기 수치
4. 기존 코드베이스의 구조와 기술적 제약

문서와 기존 코드가 충돌하면 임의로 한쪽을 덮어쓰지 말고 충돌을 요약해 사용자에게 확인한다.

## 3. 게임의 핵심 정체성
- 장르: 짧은 세션의 캐주얼 액션 디펜스 + 맵 로밍/등불 복구
- 플랫폼: Firebase를 통한 웹 배포, 모바일 브라우저 대응
- 플레이 감각: 부드러운 360도 이동, 방향·반경을 지정하는 빛 공격, 명확한 피격/구출 피드백
- 세계관: 빛의 마을과 어둠의 마을은 서로 다른 생태와 이해관계를 가진다.
- 전투의 목적은 단순 처치가 아니다. 잃어버린 빛의 주민은 빛으로 본래 모습을 되찾게 한다.
- 어둠의 패시브 주민은 공격하지 않는다. 공격하지 않고 지나가는 선택에 보상을 준다.

## 4. 현재 기획의 핵심 규칙
- 플레이어블 캐릭터: 루미(기본), 토끼(구출 후 해금), 다람쥐(구출 후 해금).
- 일반 스테이지 목표 시간: 약 100초.
- 플레이어 HP와 하트(목숨)는 구분한다. HP가 0이 되면 하트 1개를 잃고 중앙 광원 근처에서 재생성한다. 하트가 모두 소진되면 패배한다.
- 중앙 광원은 최후 보루다. 광원 상태가 최저 단계에 도달하면 패배한다.
- 등불 스테이션은 맵에 1~4개 배치한다. 첫 스테이지는 1개로 시작하고 스테이지 진행에 따라 증가시킨다.
- 비활성 등불에 빛 공격을 맞히면 일정 시간 후 활성화된다. 활성 등불은 높은 광도 상태를 유지한다.
- 모든 등불을 활성화하면 맵 전체 광도가 서서히 증가하는 보너스 효과가 발생한다.
- LP와 플레이어 주변 광도는 연동되지만, 등불/중앙 광원/맵 전체 광도는 별도 상태로 관리한다.
- 적 종류: 잃어버린 빛의 주민, 어둠의 호스틸 주민, 어둠의 패시브 주민, 보스 노월.
- 호스틸 적은 플레이어와 중앙 광원/등불을 위협한다. 잃어버린 주민은 빛을 맞고 HP가 0이 되면 본래 모습으로 돌아가 마을로 귀환한다.
- 패시브 주민은 공격하지 않는다. 공격할 수는 있지만 이득이 없으며, 공격하지 않고 근처를 지나가면 자비 점수를 얻는다.
- 일반 승리: 제한시간 종료 시 플레이어가 생존하고 중앙 광원이 유지됨.
- 완전 승리: 일반 승리 조건에 더해 중앙 광원과 모든 등불이 '밝음' 이상.
- 보스 스테이지: 보스의 HP를 0으로 만들면 승리. 세부 제한시간/중앙 광원 조건은 미확정이므로 별도 설정값으로 두고 사용자 확인 전 임의 확정하지 않는다.

## 5. 구현 원칙
- 게임 규칙과 밸런스 수치는 코드 곳곳에 하드코딩하지 말고 설정 파일 또는 상수 모듈 한 곳에서 관리한다.
- 게임 상태 업데이트는 가능하면 순수 함수/명시적 시스템으로 분리한다.
- 렌더링 프레임과 게임 시뮬레이션 시간을 분리한다. 프레임률이 달라도 이동·쿨다운·타이머가 달라지지 않도록 delta time을 사용한다.
- 충돌, 공격 판정, 적 AI, 점수, 광도 계산을 서로 분리한다.
- 모바일 터치 입력과 PC 마우스/키보드 입력을 공통 입력 인터페이스로 연결한다.
- 가상 조이스틱은 화면 크기와 방향에 맞게 배치하고, 터치 중 브라우저 스크롤/줌이 게임 조작을 방해하지 않도록 한다.
- 가로 화면을 기본으로 하되 세로 화면도 제공한다. 초기에는 반응형 레이아웃을 우선 구현하고, 세로 화면의 UI 배치가 불가능하면 회전 안내를 표시한다.
- 게임 화면은 브라우저 전체 화면에 맞추되 주소창/안전영역/노치 영역을 고려한다.
- Firebase 설정은 환경별 설정으로 관리한다. 서비스 계정 키나 비밀값을 클라이언트에 포함하지 않는다.
- 인증·랭킹·상점·광고는 핵심 플레이 검증 후 구현한다. 초기 MVP에 불필요한 서버 기능을 추가하지 않는다.
- 외부 이미지/사운드 파일을 임의로 가져오거나 저작권이 불명확한 에셋을 사용하지 않는다.

## 6. 작업 완료 보고 형식

2. 구현한 동작
3. 실행/빌드/테스트 결과
4. 남은 문제와 미확정 기획
5. 브라우저 및 모바일에서 확인할 수동 테스트 방법

- 기술 스택 및 실행 명령
- 기존 기능과 에셋
- 구버전 기획에 묶여 있는 코드
- 재사용 가능한 시스템
- 최신 기획과의 차이

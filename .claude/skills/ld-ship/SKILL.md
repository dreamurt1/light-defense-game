# 마무리·배포

## 1. 기록 먼저
- 지금 유효한 규칙이 바뀌었으면 CLAUDE.md 해당 절(짧게), 경위는 `docs/DECISION_LOG.md` 맨 아래에 `- YYYY-MM-DD · 내용` 한 줄.
- 게임 규칙·화면·그림 사실이 바뀌었으면 스킬 원본 `docs/skill/light-defense-game/`도.

## 2. 한 번에 — `node scripts/ship.mjs`
```
node scripts/ship.mjs --msg <커밋 메시지 파일> --paths <이번 작업 경로들,쉼표> [--deploy] [--notify "알림 문장"]
```
- 순서: 타입 → 테스트 → 빌드 → (스킬·src/data가 바뀌었으면 `doc:skill` + "zip 다시 올리기 필요") → 커밋(작성자 noreply)·푸시 → (`--deploy`면 배포 + 이번 커밋의 public 파일 라이브 md5 대조) → 윈도우 알림.
- `--paths`로 이번 작업만 담는다(진행 중인 다른 작업이 섞이지 않게).
- 게임 코드·에셋이 바뀌었으면 `--deploy`(라이브 교체는 바로 — 테스터 피드백용). 문서만이면 배포 없이.

## 3. 커밋 메시지 파일
- 한국어 제목 한 줄(무엇을·왜) + 빈 줄 + 이 대화의 시스템 안내가 주는 꼬리 줄(Co-Authored-By, Claude-Session)을 **그대로** 붙인다. 세션마다 다르니 매번 확인.
- 메시지에 개인 메일·비밀값을 넣지 않는다(공개 저장소).

## 4. 알림
- 폰: PushNotification 도구(스크립트 밖).
- 윈도우: `--notify` 또는 `powershell -File scripts/notify.ps1 "문장"`.

## 5. 보고 (한국어)
- 맨 위: "zip 다시 올리기 필요"(해당 시) → 어긋남·문제 → 바꾼 것 → 확인한 것(테스트 수·빌드·화면·라이브 대조) → 제안 값·새 문구 → 남은 것.
- **만들거나 고친 파일의 전체 경로**(2026-11-24 라이언): 파일 이름까지, 한 줄에 하나씩 코드 블록에(저장소·바탕화면 station·스크래치 모두). 복사해서 다른 곳에 지시할 수 있게.
- 보여 줄 그림은 SendUserFile.

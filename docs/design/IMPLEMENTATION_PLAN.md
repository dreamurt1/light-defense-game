# Implementation Plan — LIGHT DEFENSE
> 2026-11-12 결정 반영: Phase 0 완료(`docs/CODEBASE_AUDIT.md`). Phase 1에서 하트 재생성 HP 100%·무적 2초, 반자동은 대상이 없으면 쏘지 않음. 맵 3종은 스테이지 테마(Phase 5).

## Phase 0 — 기존 코드베이스 감사 (코드 변경 금지)
1. 디렉터리와 주요 엔트리 포인트 조사
2. package manager, scripts, 프레임워크, 렌더러 확인
3. Firebase Hosting 및 환경별 설정 확인
4. 기존 플레이 화면, 입력, 게임 루프, 캐릭터/적/맵/아이템 구현 확인
5. 현재 코드와 `GAME_DESIGN.md`의 차이 표 작성
6. `docs/CODEBASE_AUDIT.md` 생성
7. 위험한 대규모 변경은 사용자 승인 전 진행하지 않음

완료 조건: 사용자가 현재 구조와 마이그레이션 계획을 검토할 수 있는 보고서가 존재한다.

## Phase 1 — 핵심 플레이 프로토타입
- 기존 렌더러/프레임워크 유지
- 맵 1개, 루미 1명, 중앙 광원, 등불 1개
- 좌측 이동 입력과 우측 드래그 공격
- PC 마우스/키보드 대체 입력
- 적 1종과 잃어버린 주민 1종
- HP, 하트, LP의 기본 상태
- 100초 타이머와 승패
- 임시 도형 에셋으로도 조작감 검증 가능

완료 조건: 데스크톱과 모바일 브라우저에서 한 판을 시작하고 끝낼 수 있다.

## Phase 2 — 광원·등불·맵 탐색
- 중앙 광원 상태와 적 공격
- 등불 활성화/피격/광도 감소
- LP와 플레이어 주변 광도
- 지역별 시야 표현
- 장애물, 강/다리, 풀숲
- 모든 등불 활성화 버프
- 외곽 등불 활성화가 중앙 광원만 지키는 전략보다 유리하도록 보상

완료 조건: 플레이어가 외곽으로 나가 등불을 켜는 것이 유의미하고, 중앙 광원과 등불 모두 방어해야 한다.

## Phase 3 — 적과 주민의 행동 차별화
- 잃어버린 주민: 빛에 맞으면 구출 귀환
- 호스틸 몹: 추적/등불 공격/중앙 광원 공격 중 역할 구분
- 패시브 주민: 비공격, 통로/아이템 위치 배치, 자비 판정
- 공격하지 않고 지나가면 자비 점수
- 빛에 닿았을 때 적별 반응
- 70% 진행 시 클라이맥스 스폰 변화

완료 조건: 세 집단을 플레이어가 텍스트 설명 없이도 행동으로 구분할 수 있다.

## Phase 4 — 아이템·점수·완전 승리
- 소모형 아이템 5종
- 아이템 스폰 규칙
- 점수와 콤보
- 기본 승리/완전 승리 구분
- 결과 화면과 전투 요약

완료 조건: 플레이어가 한 판의 성과와 보상을 이해할 수 있다.

## Phase 5 — 콘텐츠 확장
- 빛의 마을/경계/어둠의 마을 3종 맵
- 등불 1~4개 스테이지 난이도
- 호스틸 몹 4종, 잃어버린 주민 4종, 패시브 주민 3종
- 토끼/다람쥐 구출 및 플레이어블 해금
- 노월 보스 스테이지
- 랜덤 이벤트 및 간단한 세계관 장면

완료 조건: 각 콘텐츠가 독립적으로 테스트되고 난이도가 급격히 튀지 않는다.

## Phase 6 — UI·모바일 최적화·Firebase 배포
- 홈/캐릭터 선택/설정/상점/튜토리얼/결과 UI
- 가로/세로 화면 대응
- 터치 입력, 안전영역, 브라우저 스크롤 방지
- 사운드/볼륨 설정 저장
- Firebase Hosting 빌드 및 배포
- 성능/메모리/네트워크 오류 확인
- 배포 전 체크리스트 실행

완료 조건: 실제 Firebase Hosting URL에서 PC와 모바일 브라우저 플레이가 가능하다.

## 구현 순서의 원칙
- 한 Phase를 끝내고 검증한 뒤 다음으로 이동한다.
- 실제 캐릭터 아트가 준비되지 않았다면 임시 스프라이트를 사용하되, 나중에 교체할 수 있는 에셋 로더 구조를 만든다.
- 랜덤 요소는 시드 또는 개발용 고정 시드를 지원해 버그 재현이 가능하게 한다.
- 우선 싱글 플레이 로컬 상태로 구현하고, 랭킹/계정/상점은 나중에 Firebase 서비스와 연결한다.

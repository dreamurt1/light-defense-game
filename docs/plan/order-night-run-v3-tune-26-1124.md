## 1. 빛 레벨 (`game.json growth`)

- `xpToNext: [10, 15, 25, 40, 60, 85, 115, 150, 190]`. `xp`·`perLevel`·`maxLevel` 그대로.
- ★10에 닿은 뒤 남는 XP는 **50마다 별가루 +1**(`growth.overflowDustPerXp: 50`, 제안). 토스트 없음, 아침 요약의 별가루에 합산.
- 다시 재기: 실력 0.5·1.0의 밤별 평균 ★ 표. 목표 ★10 도달 밤 = 0.5는 런 끝까지 ★8~9, 1.0은 밤 9~10.

## 2. 구출 밤 (`nights.json rescue`, `systems/grid.ts friendSpots`)

- `rescue.spotDist: [6, 9]` — 광장 중심(16, 9)에서 가로·세로 중 큰 값이 6~9인 바닥 칸 중 seed로 하나. 후보가 없으면 가장 가까운 바닥 칸.
- `rescue.excludeEvents: ["darkWind"]`.
- 다시 재기: 실력 0.25의 "구출 밤에 끝난 런"이 12런 중 **3 이하**면 통과. 넘으면 (나) 구출 밤 클라이맥스 적 수 ×0.8을 더한다(`rescue.climaxMultiplier: 0.8`).

## 3. 하트로 광원 되살리기 (`game.json run.sourceRevive`, `systems/stageOutcome.ts`, `Sources.ts`)

```jsonc
"sourceRevive": { "enabled": true, "hpRatio": 0.4, "maxPerNight": 1, "pushRadius": 240, "invulnSec": 2.5 }
```

- 중앙 광원 HP가 0이 되는 순간 하트가 1개 이상이면: **하트 −1**, 광원 HP를 `hpRatio`(40%)로 되살림, 빛기둥 연출(루미 부활과 같은 `fx-respawn`) 1.5초 동안 광원 둘레 `pushRadius` 안의 적을 밀어내고 광원은 `invulnSec` 무적. 토스트 "하트 하나로 광원을 다시 밝혔어요". 이벤트 `central:revived`(소리는 `player:respawn` 재사용, 진동 세 번).
- 한 밤에 `maxPerNight`(1)번까지. 그 밤에 두 번째로 꺼지면, 또는 하트가 0이면 지금처럼 런 종료("중앙 광원이 잠들었어요").
- 하트 0에서 루미가 쓰러지는 것은 그대로 종료. 튜토리얼(`practice.centralFloor`)·트라이얼은 해당 없음.
- 이야기상 이유(문구는 11절): 루미는 광원의 파편이라 제 빛(하트)으로 광원을 깨운다.
- 완료 기준 I절에 "광원 0 + 하트 ≥1 → 되살림 1회, 두 번째 → 종료" 추가. `ResultSheet` 요약에 "광원을 되살린 횟수"는 넣지 않는다(통계 6칸 유지).
- 다시 재기: 런이 끝난 까닭이 "하트 0"과 "광원"으로 나뉘는지. 평균 밤이 목표(0.5 → 5~8, 1.0 → 10~12)를 넘어가면 5절의 곡선으로 되돌린다.

## 4. 밤 1~3 고정값 + 밤 4부터 곡선 (`nights.json spawn`)

```jsonc
"overrides": {
  "1": { "normal": { "maxAlive": 3, "interval": [4.0, 3.0] }, "climax": { "maxAlive": 6,  "interval": [2.4, 2.0] } },
  "2": { "normal": { "maxAlive": 5, "interval": [3.0, 2.4] }, "climax": { "maxAlive": 8,  "interval": [1.8, 1.5] } },
  "3": { "normal": { "maxAlive": 7, "interval": [2.4, 1.8] }, "climax": { "maxAlive": 10, "interval": [1.5, 1.2] } }
}
```

(옛 stage-1·2·3의 값 그대로. 로스터·호스틸 비율·행렬은 표대로.)

- 밤 4부터는 곡선을 **밤 3 값에서 이어지게** 다시 맞춘다. 시작점: 보통 `maxAlive = 7 + 0.7×(n−3)`(상한 20), `interval = [2.4, 1.8] × 0.92^(n−3)`(하한 [0.4, 0.3]) / 클라이맥스 `10 + 1.3×(n−3)`(상한 28), `[1.5, 1.2] × 0.92^(n−3)`(하한 [0.3, 0.24]). 이 수치는 출발점일 뿐이고, 자동 플레이로 **평균 밤 0.5 → 5~8, 1.0 → 10~12**를 맞추되 **어느 밤도 전 밤보다 동시 최대가 적거나 간격이 길지 않게**(`nightRules.test.ts`에 단조 증가 테스트 추가).
- 1·2·3절과 함께 바뀌므로 세 가지를 다 넣고 한 번에 잰다(실력별 12런, 새 seed). 보고에 밤별 평균 ★·하트·끝난 까닭·맵을 표로.

## 5. 밸런스 되돌림 규칙

측정이 목표를 벗어나면 손대는 순서: ① 밤 4+ 곡선(`maxAlivePerNight`·`intervalPerNight`)만 → ② `sourceRevive.hpRatio`(0.4 → 0.3) → ③ `xpToNext` 뒤쪽 세 값. 적 수치·아이템·하트 수는 손대지 않는다.

## 6. 새 맵 3장 — 검토 결과

A3·B2·C1 모두 기획 세션에서 다시 검사(33×19, 광장, 둘레 띠, 연결, 등불 4곳 거리 4~8, 덩어리 크기, 다리) **통과**. 배치·이름 그대로 채택. 메모만 셋:

- B2: 북쪽 등불 둘이 강 건너에 있어 다리가 자연스러운 길목이 된다 — 의도대로. 행렬이 다리 위에서 길을 막는 장면이 나오는지 한 번 확인(헤드리스 캡처 한 장).
- C1: 돌담 고리와 안쪽 가림벽으로 "미로" 느낌이 난다. 밤 6+에 C1·B1·B2를 섞는 것은 C2가 올 때까지의 임시로 승인. **C2 '외곽 · 깊은 숲'**(건초더미·바위가 많고 통로가 긴, 노월이 나오기 좋은 지형)은 다음 주 일감으로 남긴다.
- A3: 꽃 덤불 여덟이 모두 풀숲 규칙(은신)이라 밤 1~2가 숨기 쉽다 — 손맛 확인 뒤 필요하면 두 덤불을 바위로.
